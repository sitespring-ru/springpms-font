# Обновление иконочного шрифта из экспорта IcoMoon

Шрифт тянут по тегу несколько проектов экосистемы springpms из приватного
`sitespring-ru/springpms-font`. Поэтому цена ошибки — сломанные иконки сразу во
всех проектах, и главная задача скила — не потерять и не переименовать
существующие иконки.

Работу делает `scripts/sync-export.mjs`: он парсит экспорт, показывает диф
иконок и перегенерирует исходники в формате репозитория (namespace
`.springpms-icon`, `string.unquote` для кодпоинтов, preamble сохраняется
байт-в-байт). Вручную scss не переписывать — там 600+ строк, легко разъехаться.

## 0. Подготовка

```bash
cd "$(git rev-parse --show-toplevel)"
[ -d node_modules ] || npm ci          # без этого `npm run build:demo` упадёт: sass не найден
git fetch --tags origin                # клон бывает shallow и вообще без тегов
git status --short                     # рабочее дерево должно быть чистым
```

Если рабочее дерево грязное — остановиться и спросить, что делать с правками.

Отметить (и сказать пользователю), если `HEAD` ушёл вперёд последнего тега:

```bash
git log --oneline "$(git tag --list 'v*' --sort=-v:refname | head -1)"..HEAD
```

Эти коммиты попадут в новый тег вместе с иконками.

## 1. Найти экспорт

Путь берётся из запроса пользователя. Принимается и папка, и `.zip` прямо из
загрузок (`~/Downloads/icomoon.zip`) — скрипт сам распакует и спустится во
вложенную папку. Если путь не назван — спросить, не угадывать.

## 2. Сухой прогон

```bash
node .claude/skills/update-icon-font/scripts/sync-export.mjs <путь> 
```

Скрипт печатает отчёт и блок `===SUMMARY-JSON===` с полями `added`, `removed`,
`moved`, `breaking`, `suggestedBump`. Показать пользователю список добавленных
иконок.

### Ворота

- **`БЛОКЕРЫ` в выводе (exit 2)** — не применять. Обычно сбиты настройки
  проекта IcoMoon (имя шрифта, префикс классов) или в экспорте нет одного из
  форматов. Передать пользователю текст блокера: чинится это на стороне IcoMoon
  переэкспортом.
- **`removed` непустой** — остановиться и спросить. Удаление иконки ломает все
  проекты, где используется её класс. Продолжать только по прямому «да», и тогда
  это major.
- **`moved` непустой** — не блокер (потребители обращаются к `$icon-*` и
  `.icon-*`, а не к кодпоинтам), но упомянуть: значит, проект в IcoMoon
  пересобирали, и захардкоженные где-то `\e9xx` перестанут совпадать.

## 3. Применить и собрать

```bash
node .claude/skills/update-icon-font/scripts/sync-export.mjs <путь> --apply
npm run build:demo
```

Скрипт трогает `src/fonts/`, `src/variables.scss`, `src/style.scss`,
`src/demo.html`, `src/demo/`. `src/style.css` — это коммитимый артефакт сборки,
его делает `build:demo`; в коммит он должен попасть обязательно.

## 4. Проверить

```bash
grep -cE '^\$icon-' src/variables.scss          # иконки + 1 ($icon-font-family)
grep -c '&\.icon-' src/style.scss               # должно быть на 1 меньше
grep -c '^\.springpms-icon\.icon-' src/style.css   # == предыдущему
grep -c 'class="glyph' src/demo.html            # == предыдущему
```

Все переменные должны быть использованы (вывод пустой):

```bash
comm -3 \
  <(grep -oE '^\$icon-[A-Za-z0-9_-]+' src/variables.scss | sed 's/^\$//' | grep -v '^icon-font-family$' | sort) \
  <(grep -oE '&\.icon-[A-Za-z0-9_-]+' src/style.scss | sed 's/^&\.//' | sort)
```

И глазами по демо — открыть `src/demo.html` в браузере, найти новые иконки,
убедиться что рисуются глифы, а не квадраты (квадрат = бинарник шрифта не
совпал со стилями). Для этого можно использовать браузерные инструменты
claude-in-chrome; если они недоступны — попросить пользователя открыть файл.

## 5. Версия

Формат тега — `v<x.y.z>` (`v2.5.3`; безпрефиксный `2.4.1` — legacy, не повторять).

База = максимум из последнего тега и `version` в `package.json` — исторически
`package.json` отставал от тегов, поэтому смотреть надо на оба:

```bash
git tag --list 'v*' --sort=-v:refname | head -1
node -p "require('./package.json').version"
```

Инкремент:

| Что в дифе | Бамп | Прецедент |
|---|---|---|
| добавлены иконки | **minor** | `v2.5.0` «add max and basik» |
| только пересборка / правки стилей | **patch** | `v2.5.1`…`v2.5.3` |
| иконки удалены или переименованы | **major** | только после явного «да» |

```bash
npm version <новая-версия> --no-git-tag-version   # обновит package.json + package-lock.json
```

`package.json` и тег обязаны совпадать — это то, по чему потребители понимают,
что тянуть.

## 6. Коммит и тег

Сначала показать пользователю итог — список иконок, новую версию, `git status
--short` — и **дождаться подтверждения**. Коммит и тег без прямого «да» не
делать.

Стиль сообщений в истории — короткая строчка в нижнем регистре: `add max and
basik`, `updates and fixes`, `move icons to font namespace`. До трёх иконок
перечислять по именам, дальше — `add N icons`.

```bash
git add -A
git commit -m "add jacuzzi and ski_pass"
git tag -a v2.6.0 -m "add jacuzzi and ski_pass"
```

## 7. Пуш — не делать

Отдать пользователю отдельной строкой, чтобы выполнил сам:

```
! git push origin main --follow-tags
```

## Полезно знать

- В экспорте лежит `selection.json` — файл, которым проект открывается обратно в
  IcoMoon. До `v2.5.3` он коммитился в `src/`, потом его выкинули. Если
  пользователь захочет вернуть возможность доредактировать набор — предложить
  положить его обратно, скрипт его не трогает.
- `.eot` намеренно не публикуется (IE), скрипт его пропускает и говорит об этом.
- `?4jfbtf` в `@font-face` — cache-buster IcoMoon, он меняется на каждый экспорт;
  скрипт подставляет новый и в `style.scss`, и (через сборку) в `style.css`.
